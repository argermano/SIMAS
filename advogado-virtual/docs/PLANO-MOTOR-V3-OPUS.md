# Motor de Peças v3 — "Sessão de Lapidação" (iterativa, com o dossiê, comercializável)

> Fonte: 2 exploradores (≈80 arquivos do repo), referência oficial da API Anthropic (2026), 2 planejadores (arquitetura / produto). Decisões do dono em 2026-08-14: **híbrido** (Fase 0 API + Fase 1 Managed Agents), **créditos em R$**, **biblioteca própria + domínios de tribunais**. Execução: Opus, por fases, com revisão adversarial (padrão da casa).

## 1. Contexto — por que mudar

**Como o escritório trabalha hoje** (relato do dono): a peça sai do motor do SIMAS e a lapidação acontece FORA — no claude.ai (Max) e no Cowork+Chrome: rodadas de instrução, PDFs grandes (16 fichas financeiras, SGP, normas, GFE, regulamento PS-II, ACT 2025/2027), estouro do limite de ~100 arquivos/páginas → conversas novas (contorno via Drive); conferência de jurisprudência com Cowork+Chrome em 3 rodadas (TST, TRT-10/12/6, Falcão, ~40 acórdãos) que pegou turma/ano errados, **Súmula 294 cancelada (jun/2025)** e acórdão do TRT-12 **reformado** (mudou o foro para Brasília, Verbete 82/2025 do TRT-10); planilha com 3 cenários anexa.
**Conclusão**: a peça gerada nunca é a final. O advogado refina em rodadas, anexa provas, verifica. Precisa existir DENTRO do SIMAS — para o escritório e, comercialmente, cobrando o uso de IA.

**Fatos do código (exploração):**
- Motor single-turn (5 chamadas, `messages:[{user}]`); **zero** prompt caching, tool use, structured outputs, thinking/effort; teto `MAX_PROMPT_CHARS=600k` → 413; docs como texto bruto (`MAX_CHARS_POR_DOC=30k`), sem RAG. SDK `@anthropic-ai/sdk` 0.78 (Managed Agents exige ≥0.88).
- Iteração: `refinamento-peca` cria PEÇA NOVA por rodada; `editor-documento` (comando livre) sem contexto do caso/histórico/cota; `ChatDiagnostico` único multi-turno, não persiste; rota `refinar-peca` morta. Já bons: `pecas_versoes`, `ComparadorSecoes` (aceite por seção), guarda anti-encolhimento (70%/2000), rede de segurança `after()`, `recuperarPecaCompleta`, `taxa_edicao`, workflow de revisão, materialização idempotente no dossiê + Drive.
- Jurisprudência: `verificarCitacoes` (CNJ mod 97-10, súmulas por faixa, 24 leis) + online (LexML federal, DataJud contagem; 25 consultas; "online nunca cria ✗"); DataJud = estatística; `teses_escritorio` (15 aprovadas injetadas). `SUMULA_MAX`/`LEIS_CONHECIDAS` hardcoded envelhecem.
- Medição: `api_usage_log` bom (tokens/custo/latência) mas **cota por CONTAGEM de chamadas/mês**; sem créditos/billing (D1 despriorizado 07/2026); `USD_BRL=5.70` hardcoded; `PRECOS_1K` sem opus-5/sonnet-5 nem tokens de cache; `editor-documento`/`chat-diagnostico` sem cota.
- Infra: Vercel `maxDuration=300` (uma geração já leva 150–275s), sem fila de IA; VPS só proxy DJEN.

## 2. A pergunta do Max — resposta
**Não dá para o SIMAS usar a conta Claude Max.** Max é licença de uso interativo pessoal nos produtos Anthropic (claude.ai, Claude Code, Cowork); não há API do Max; embutir no produto (ainda mais multi-tenant) viola os termos e arrisca a conta da equipe. O SIMAS usa a **API** (por token; a conta que ficou sem créditos no bot) e cobra por **créditos**.
Divisão honesta: **migra para o SIMAS** a lapidação COM o dossiê (sessão persistida, anexos, propostas com diff, verificação, versões, exportação, custo medido); **continua no claude.ai/Cowork (Max)** a varredura ampla em portais com navegador e a exploração livre — até o SIMAS ter fonte própria (biblioteca). Posicionamento: SIMAS = sistema de registro + editor + agente de lapidação com o dossiê; "a IA propõe, o advogado aplica".

## 3. Plataforma (referência oficial 2026) — o que muda o jogo
1M de contexto, 128K de saída; Files API (sobe 1×, referencia N×); prompt caching (leitura 0,1×); compaction server-side; tool use + server tools (`web_fetch`/`web_search` com `allowed_domains`, `code_execution`); structured outputs; **Managed Agents (beta)**: loop na Anthropic, container por sessão com arquivos montados, eventos SSE, **session budget em USD (teto duro)**, memória, subagentes, webhooks — resolve os 300s da Vercel sem fila própria. Preços: opus-5 $5/$25, sonnet-5 $3/$15 (intro $2/$10 até 31/08/2026), haiku-4-5 $1/$5.

## 4. Arquitetura (decidida: híbrido)
- **`SessaoDriver`** com 2 implementações e a MESMA UI/dados/ferramentas: `messages` (Fase 0: 1 request streaming por rodada, cache + compaction, dentro dos 300s) e `managed` (Fase 1: Managed Agents; Vercel = cliente fino: envia eventos, resolve tools custom, proxy SSE com reconexão por cursor, webhooks + cron de pendências). Se o beta mudar, a Fase 0 segue funcionando.
- **A verdade da peça** continua em `pecas.conteudo_markdown` + `pecas_versoes`; o agente **propõe** patch por seção, o advogado **aceita** (`ComparadorSecoes`) → só então vira versão. Materialização só em aprovar/exportar (inalterado).
- **Modelos**: lapidação `claude-sonnet-5` (padrão) / `claude-opus-5` (avançado; criação/revisão crítica); leitura em massa `claude-haiku-4-5`. Modelo **fixo por sessão** (trocar invalida cache). Adaptive thinking + `effort` no avançado. Fable 5 NÃO (retenção 30d obrigatória).
- Vercel 300s no driver MA: `GET /api/pecas/[id]/sessao/[sid]/stream` abre o stream de eventos + `events.list` desde `ultimo_evento_id`, deduplica, persiste, resolve `agent.custom_tool_use` inline, repassa SSE; aos ~270s emite `reconnect`. Tool pendente sem ninguém conectado → `resolverFerramentasPendentes` via webhook `session.status_idled` + cron `/api/cron/sessoes-ia` (*/5).

## 6. Contexto sem "limite de 100 arquivos"
1) Dossiê como **recursos**, não prompt: `src/lib/ia/sessao/recursos.ts` — `garantirArquivoAnthropic(doc)` (Files API 1×, `documentos.anthropic_file_id`), mounts `/workspace/dossie/<nn>-<slug>.pdf` + `.txt` do texto extraído + `INDEX.md` (id, nome, tipo, páginas, resumo, path); o agente faz grep/read no container. 2) Extração **por página** (`documentos_paginas`, OCR Haiku por lote) → `ler_documento(id, pág_ini, pág_fim)` pagina de verdade. 3) **Resumo automático** (`src/lib/documentos/resumir.ts`, Haiku ~300 tokens) para docs >30k chars, no upload. 4) Leitura em massa delegada ao subagente `simas-leitor-dossie` (Haiku) + python para tabelas (16 fichas × 50 pp ≈ US$0,40 Haiku + US$1 Opus). 5) **Caching**: MA automático; driver `messages` com breakpoints tools → system → dossiê (ordem determinística) → histórico, TTL 1h, verificar `cache_read_input_tokens>0`. 6) **Compaction** (MA automática; `messages` via beta `compact-2026-01-12`, preservando `response.content`). 7) Anexar no meio: `sessions.resources.add` + INDEX atualizado; no `messages`, entra no prefixo na próxima rodada. 8) Tools devolvem ≤40k chars + path do resto.

## 10. Cobrança (decidida: créditos em R$) e medição
- **Medidor primeiro** (pré-requisito): `PRECOS_1K` → `PRECOS_MTOK` com cache read/write e vigência (opus-5 5/25, sonnet-5 3/15 [intro 2/10 até 31/08], opus-4-8 5/25, sonnet-4-6 3/15, haiku 1/5, fable 10/50); `logUsage` com cache/sessão/turno; `USD_BRL` e markup em `tenants.ia_config`; no MA o custo autoritativo vem de `session usage/list_cost`; fechar superfícies sem cota.
- **Unidade**: 1 crédito = R$ 1 faturado; débito = custo de lista × câmbio × markup (padrão 2×). O advogado vê R$, nunca tokens. **Franquia por plano** (estimativa inicial, validar no piloto): Trial R$ 40 únicos; Básico R$ 60/mês; Profissional R$ 200/mês; Escritório R$ 500/mês. **Pacotes** pré-pagos (R$ 50/150/500 → 50/160/560 cr, validade 12 meses). **Tetos**: por sessão (padrão por plano; pausa, nunca corta no meio da rodada), mensal por tenant, e spend limit no Console Anthropic (workspaces "SIMAS-interno" e "SIMAS-clientes"). **Grátis**: verificação determinística, diff/aceite, versões, exportação, teses. **Prévia de custo** antes de: iniciar sessão, Avançado, anexar PDF grande, revisão crítica, retomar com contexto expirado. Papéis: estagiário só Padrão.
- **Plano `interno`** (escritório do dono): sem débito, mesmo medidor, orçamento mensal sugerido R$ 1.000 de custo real com alertas 50/80/100% (ao bater, bloqueia só Opus/revisão crítica), **fatura simulada** mensal para calibrar preços.
- Custo estimado por peça (lista, 5,70, cache): rotineira ≈ R$ 4 (fatura 2× ≈ R$ 8); média ≈ R$ 17 (≈ R$ 35); complexa (16 fichas + ACT, Opus, 10 rodadas) ≈ R$ 45–58 (≈ R$ 90–115). Alavancas: pré-processar dossiê 1×, Opus só criar/revisar, revisão crítica sob demanda.
- Gateway/invoice (Asaas/Pix) = D1, fora deste plano; painel admin cross-tenant entra na Fase 3.

## 11. Jurisprudência (decidida: biblioteca própria + domínios de tribunais)
Prometer: CNJ válido e existente (DataJud), lei federal existe (LexML), súmula na faixa, teses/biblioteca do escritório sem `[VERIFICAR]`, qualquer julgado "de memória" marcado. Não prometer: navegação completa em portais, cobertura total. Roadmap: (1) biblioteca de acórdãos (PDF + metadados Haiku + status vigente/reformado/superado + "conferido por/em") — só ela é citável sem `[VERIFICAR]`; (2) `web_fetch` em domínios de tribunais (advogado cola URL → agente lê, extrai, grava na biblioteca com data de acesso); (3) tabela curada de súmulas canceladas/superadas + rotina de atualização de `SUMULA_MAX`/`LEIS_CONHECIDAS`; (4) ponte com o Cowork: exportar a lista de citações `conferir`/`nao_verificada` e receber o veredito na biblioteca; (5) Escavador/Jusbrasil só como add-on após o piloto; (6) sinal de "movimento recursal posterior" via DataJud.
